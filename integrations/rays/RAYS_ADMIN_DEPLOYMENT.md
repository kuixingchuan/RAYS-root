# RAYS 专属管理平台运行说明

## 数据边界
管理平台不提供公共数据管理。个人原图、预览、EXIF、GPS、相册、评分、标签和本地索引始终留在设备内；平台只管理独立账号及服务端运行数据。

## 组件
- RAYS 后端：`server`，新增 `/api/v1/admin/**`。
- 管理端：`C:/kaifa2/RAYS-root/mayfly-go`，前端首页为 RAYS 管理台；Go 后端提供 `/api/rays/**` 代理。
- 账号、会话与操作审计继续存放在 RAYS PostgreSQL；Mayfly 操作员账号使用自己的数据库。

## 配置
RAYS 与 Mayfly 的进程环境同时设置相同的 `RAYS_ADMIN_BRIDGE_TOKEN`，使用安全随机生成的不少于 32 字符的凭据。不要写入代码、浏览器配置或 Git。

Mayfly 另需：
- `RAYS_ADMIN_API_URL`：内网 RAYS 地址，例如 `http://api:8080`，只能填写协议和主机端口，不带路径。
- `RAYS_ADMIN_OPERATOR_IDS`：明确授权的 Mayfly 操作员 ID，逗号分隔，例如 `1,3`；未设置时所有操作员均拒绝。管理端访问令牌与刷新令牌绑定服务端会话代次，退出会撤销旧代次；访问和刷新令牌不能混用。升级后旧令牌需要重新登录。多实例部署应按 Mayfly 原有配置共享 Redis 缓存。

`deploy/compose.production.yml` 已将桥接凭据传给 RAYS。正式管理服务应与 RAYS 在可信内网通信；跨主机应使用 HTTPS。不要通过公开 Caddy 域名访问管理 API：该网关已明确返回 404。同样阻止旧 local-admin 接口进入公网。

Mayfly 原有账号登录、验证码和双因素设置继续保留。独立 QA 数据库为了自动化测试关闭了验证码，生产默认配置未修改。首次正式运行应设置自己的管理员凭据与权限，不沿用上游默认密码。

## 构建与启动
RAYS 使用 JDK 21 和 `server/mvnw.cmd`。首次启动自动执行 V12 审计表迁移。

Mayfly 使用 Go 1.26；在其 `server` 目录执行 `go build -mod=mod .`，按原有方式配置 `config.yml` 后启动。保留既有机器、数据库和容器入口，可按实际部署资源添加受限运维连接。

Mayfly 前端使用 Node 24，在 `frontend` 中执行 `npm ci` 和 `npm run build`。已锁定依赖解析文件；Vue 使用与现有组件兼容的稳定系列，移除未使用的实验插件注册。开发服务器默认代理 `localhost:18888`。

## 管理能力
账号查询、邀约创建、昵称/语言修改、禁用/解禁、逻辑删除、撤销全部会话；操作审计；数据库与 API 状态、运行时间、登录限流参数；过期会话整理。禁用、删除或注销会话后，每次访问都会验证数据库状态；解禁不会复活旧会话。

账号变更与对应审计同一事务提交。审计只包含操作者 ID、动作、目标 ID 和时间，不保存登录身份明文、验证码、访问凭据或照片。

## 备份恢复
沿用 `scripts/deploy/backup_database.sh` 和 `restore_database.sh`。它们运行在服务器端；恢复涉及目标数据库覆盖，必须显式指定并确认目标库。管理网页不提供任意命令执行接口。

Windows 隔离演练使用 `scripts/deploy/test_admin_backup.ps1`；脚本仅接受 `rays-admin-qa-数字` 专用容器，恢复到新建随机数据库并核对数据，随后清理恢复库。它不接受生产数据库目标。

## 部署范围
本次验证针对本机独立测试环境，不包含真实生产主机、域名证书签发、真实邮件/短信/微信外部服务或生产备份恢复。这些需要对应环境凭据与部署目标后单独验收。
